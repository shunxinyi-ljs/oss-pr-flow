# 名额判据（闸门一开头执行）

## 判断是否受限

```
gh api repos/{owner}/{repo} --jq '.permissions.push'
```

- `true`：有写权限，不受 open PR 数量限制，正常侦察。
- `false`：外部贡献者，继续下一步。

## 统计自己的在途 PR

```
gh pr list --repo {owner}/{repo} --author @me --state open
```

GitHub 对外部贡献者有单仓库 open PR 上限（常见为 2，仓库可配置，以实际为准）：

- 在途数 < 上限：正常侦察、正常选题。
- 在途数 ≥ 上限：**停止侦察**。只允许从已有候选或已搁置清单里挑价值最高的一个继续推进（等已有 PR 被合并或关闭腾出名额后才发），其余记录搁置原因。配额满时继续找新候选是无效工作。

## top n 选序依据

只剩少量名额时，按以下三项排序选最值得做的：

1. **影响面**：多少用户、多少代码路径受影响。
2. **被驳回风险**：维护者对同类改动的历史态度、是否触碰核心设计。
3. **证据强度**：复现路径和测试是否现成。

禁止用"哪个更容易写"排序——容易写和价值高没有相关性。

## 创建 PR 返回 404 的鉴别

外部贡献者 `POST /pulls` 返回 404 时，不要急于推断为权限问题或账号滥用抑制。先核对在途数是否已达上限——名额满时的报错表现可以是 404。确认方式：网页端手动发起 PR，看是否提示已达到本仓库的开放拉取请求上限。
